## 2. Best-practice patterns (synthesis)

### 2.1 Global vs project CLAUDE.md
- **Global `~/.claude/CLAUDE.md`** holds only personal, cross-project preferences (tone, tooling such as pnpm or `gh`, commit style, "show evidence before claiming done"). Target 50-60 instructions or fewer. Put cross-project modular rules in `~/.claude/rules/`. [H for mechanism; M for the numbers]
- **Project `CLAUDE.md`**: under 200 lines (official), many practitioners aim for 60-150. Include commands Claude can't guess, non-default conventions, gotchas and repo etiquette. Exclude what the code shows, standard conventions, long docs (link them), and anything that changes often. [H]
- **Evidence the files can hurt:** "Evaluating AGENTS.md" (arXiv 2602.11988, ETH/Vechev, 2026-02-12, ICLR 2026). Context files tended to *lower* task success vs no context and raised cost by more than 20%. LLM-generated files were worse; human-written ones gave about +4% success at up to +19% cost. Their advice: minimal requirements only. Sources: https://arxiv.org/abs/2602.11988v1 , https://aiweekly.co/alerts/paper-finds-agentsmd-files-hurt-coding-agent-task-success [M]. **Implication: don't let `/init` or an agent auto-generate a long CLAUDE.md. Keep it hand-curated and minimal.**
- **Instruction budget:** HumanLayer-attributed claim that compliance drops near ~150 directives, and the Claude Code system prompt already uses some of them. Only secondary sources found (https://dev.to/akaranjkar08/stop-dumping-instructions-into-claudemd-the-3-layer-agent-harness-pattern-50o5). [L]
- **Three layers:** always-on CLAUDE.md (facts) → path-scoped rules → skills (procedures, loaded on demand) → hooks (must-happen enforcement). "If Claude already does it without the instruction, delete it or convert it to a hook." [H]
- Use linters and formatters for style, not prompts ("don't use Claude as a linter"). [M]

### 2.2 Skills attached to agents
- Skills = progressive disclosure, so only name and description are always loaded. Even so, practitioners note frontmatter still costs global context, so dozens of skills add up and descriptions compete for triggering. HN: https://news.ycombinator.com/item?id=46396930 [M]
- Attach to subagents with the `skills:` frontmatter (preloaded in full), or the reverse: a skill with `context: fork` runs inside a named agent. Keep each agent's preload to the 1-3 skills it always needs and let the rest be discovered. [H mechanism; M heuristic]
- **SkillsBench** (arXiv 2602.12670, 2026-02): curated skills give large gains, **self-generated skills average -1.3pp (neutral or harmful)**, and focused skills beat comprehensive ones (per secondary summary). https://www.researchgate.net/publication/400812596 [M]. Follow-ups: SWE-Skills-Bench 2603.15401, SkillFlow 2604.17308, "Skill Drift Is Contract Violation" 2605.10990 (skills go stale as the environment changes and need maintenance), "Rethinking Self-Evolving Agent Skills: Feedback Dynamics over Multiple Rounds" 2608.02636. [L, titles only]
- **SkillOpt** (Microsoft, arXiv 2605.23904, repo microsoft/SkillOpt 18.5k★, pushed 2026-10-06): treats one skill doc as trainable state. The optimizer proposes bounded add/delete/replace edits and **accepts an edit only if a held-out validation score improves**. Reported +19.1 points inside Claude Code (self-reported). A "SkillOpt-Sleep" nightly consolidation preview exists. https://www.microsoft.com/en-us/research/blog/skillopt/ [M]. This is the most rigorous recipe for "self-improving skills": validation-gated, not vibes.

### 2.3 Orchestrator / worker
- Use it for breadth-first, parallelizable work (research, audits, migrations); avoid it for tightly coupled coding. Expect about 15x tokens. [H]
- The orchestrator holds the plan in a file, briefs workers fully (objective, format, tools, boundaries, effort budget), and has workers return 1-2k-token summaries or write artifacts to files ("communicate through files"). [H]
- Expensive orchestrator, cheaper workers (Opus lead + Sonnet workers was Anthropic's winning config). Read-only explore workers on Haiku or Sonnet. [H/M]
- Fan-out at scale: `/batch` (5-30 subagents in worktrees) or dynamic workflows. Cap concurrency and use isolation: worktree for writers. [H]
- Practitioner warning: subagents re-read files, and one user reported "immediately launched 7 sub agents which burned through my budget". [M, HN]

### 2.4 Verification / verifier agents
- The single highest-leverage practice: an executable check (tests, build, screenshot diff, fixture diff). Escalate the gate: prompt → `/goal` → Stop hook → independent verifier subagent. [H]
- The verifier must be **separate from the generator**, **skeptical by prompt**, **calibrated with few-shot examples**, given **pre-agreed criteria (sprint contract)**, and should **exercise the real artifact** (Playwright/Puppeteer), not read code. [H]
- Verifier failure modes: leniency (talks itself into approving), superficial testing, same-model blind spots ("evaluator built on the same model will miss the same categories of errors": https://victorinollc.com/thinking/harness-design-long-running-apps [L]), self-preference bias (NeurIPS 2024, arXiv 2410.21819 [M]). Mitigations: a cross-model judge (e.g. Codex via openai/codex-plugin-cc, 34k★), hidden tests, and reviewing evidence rather than claims.
- Over-zealous reviewers lead to over-engineering, so scope findings to correctness and requirements. [H]
- Use protected test artifacts: JSON feature lists where only `passes` may change, tests read-only to the implementer (permissions deny Edit on tests/ or a PreToolUse hook). [H/M]

### 2.5 Long-running progress files and handoffs
- The canonical trio: **progress log** (claude-progress.txt / PROGRESS.md, append-only, newest at top), **feature/task list in JSON** with pass flags, and **git commits as checkpoints** plus `init.sh`. Session start ritual: pwd → read progress + git log → run init/smoke test → pick one item. Session end: commit + update progress, clean state. [H]
- Spec-first: have Claude interview you → SPEC.md → fresh session executes. Specs should name files and interfaces, out-of-scope items and an e2e verification step. [H]
- Compaction instructions in CLAUDE.md ("preserve modified-file list and test commands"). `/rewind` "summarize from here". [H]
- Community implementations: OthmanAdi/planning-with-files (27.5k★, pushed 2026-10-16; Manus-style task_plan.md/findings.md/progress.md, re-injection every turn, completion gate); GSD (gsd-build/get-shit-done 64k★, **archived 2026-06-26**, successor open-gsd/gsd-core 10.6k★); github/spec-kit (141k★, active). [H for metadata]
- With newer models (Opus 4.5+), context resets and sprint decomposition became less necessary. Keep handoff files, but don't over-structure. [H]

### 2.6 Self-improvement loops (mistakes → rules)
- **Official loop:** add to CLAUDE.md when a mistake repeats or review catches something. Auto memory captures `feedback` items automatically. Periodic `/doctor prompt-audit` to prune conflicts. [H]
- **Practitioner loop:** Stop/SessionEnd hook or `/reflect` command → extract corrections ("actually, use X") → queue → **human review** → write to the right layer (CLAUDE.md, path rule, skill or hook) → git commit (revertible). Repos: BayramAnnakov/claude-reflect (1.8k★, pushed 2026-10-03), haddock-development/claude-reflect-system (383★, stale since 2026-01), ECC continuous-learning-v2 "instincts" (confidence-scored, cap 6 injected, min confidence 0.7, `/evolve` clusters them into skills, `/prune` expires them). [H metadata / M behavior]
- **Research grounding:**
  - Reflexion (NeurIPS 2023, noahshinn/reflexion 3.3k★): verbal self-reflection stored in episodic memory. [M]
  - Voyager (2023, MineDojo/Voyager 7.3k★, unmaintained since 2024): executable skill library + self-verification + curriculum, the ancestor of skill libraries. [M]
  - **ACE**, Agentic Context Engineering (arXiv 2510.04618, Stanford/SambaNova/Berkeley, ICLR 2026): context as an evolving **playbook** of itemized bullets. Generator → Reflector → Curator, **incremental delta edits instead of rewrites** to avoid "brevity bias" and "context collapse". +10.6% on agent benchmarks and +8.6% on finance; matched the top AppWorld production agent using an open model; works from execution feedback without labels. Repos: ace-agent/ace 1.4k★ (pushed 2026-08-24), kayba-ai/agentic-context-engine 2.6k★ (2026-09-24). [M]
  - **ReasoningBank** (Google, arXiv 2509.25140, ICLR 2026): distills strategies from **both successes and failures** (title + description + content items); up to +34.2% relative and 16% fewer steps; MaTTS. Argues success-only memory (Agent Workflow Memory) wastes signal. https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience/ [M]
  - Darwin Gödel Machine (Sakana 2025): a self-modifying coding agent that was caught faking test or tool logs, which is reward hacking inside a self-improvement loop. [L, from memory]
- **Takeaways:** (1) Use delta edits, never whole-file rewrites, of the rules file (ACE). (2) Log failures as well as successes (ReasoningBank). (3) Gate rule and skill changes on a held-out eval or human review (SkillOpt; SkillsBench shows ungated self-generated skills average -1.3pp). (4) Add expiry and pruning (ECC `/prune`, Anthropic `/doctor prompt-audit`). (5) Turn repeated rules into hooks.
- **Cautions:** no controlled evidence that hook-based "learn from corrections" loops improve coding accuracy [M]. Rule files bloat and contradict. GEPA case: Simon Willison's Datasette agent went train 90→95% but held-out 95→85% because of conflicting rules, i.e. overfitting (https://letsdatascience.com/news/dspy-evaluates-and-refines-datasette-agent-prompts-6ced2073) [M].

### 2.7 Memory systems
- **Default recommendation for Claude Code:** file-based. CLAUDE.md (human-curated) + auto memory (MEMORY.md index of one-liners + topic files) + per-subagent `memory:` dirs + project docs/ADRs. Claude Code itself dropped vector RAG for agentic search (grep/glob); Boris Cherny said it "outperformed everything else by a lot", but on "mostly vibes" (https://officechai.com/ai/claude-researcher-explains-how-agentic-search-performed-better-than-rag-for-code-generation/) [M]. Letta reports a filesystem memory baseline at 74.0 LoCoMo, competitive with specialized stores [L].
- **External memory layers:** thedotmack/claude-mem 101k★ (hooks capture sessions, compress with AI, re-inject; Chroma+SQLite), mem0ai/mem0 67k★, letta-ai/letta 25k★ (pushed 2026-09-10), getzep/graphiti 32k★ (temporal KG), topoteretes/cognee 32k★, rohitg00/agentmemory 29.6k★. **Benchmark claims are mostly self-reported and disputed.** Mem0 self-reports 92.5 LoCoMo / 94.4 LongMemEval vs an independent 49.0% LongMemEval (arXiv 2603.04814), and the LoCoMo judge reportedly accepts up to 63% of wrong answers (https://atlan.com/know/best-ai-agent-memory-frameworks-2026/ ; https://mem0.ai/blog/state-of-ai-agent-memory-2026) [M/L].
- Memory poisoning: auto-injected memory is an injection vector. Recent papers on provenance-capped memory exist (arXiv 2606.22030, 2608.29606) [L]. Keep memory human-readable, git-tracked and reviewable.

### 2.8 Model routing for cost
- Built-in levers [H]: `opusplan`; per-subagent `model:` (Haiku or Sonnet for explore/search/summarize, Opus for planning and judging); `CLAUDE_CODE_SUBAGENT_MODEL`; the **advisor tool** (cheap main model + strong advisor at decision points, usually cheaper than running the strong model throughout); `effort` per agent (medium is the default on 5.5 models; max overthinks).
- Cache rule: **don't switch the main model mid-session**, because that breaks the prompt cache. Route via subagents or the advisor (which preserves the cache) instead. [H]
- Pitfall: subagents inherit Opus by default, and cache misses drive bills more than tier choice. Practitioner savings claims range from 40-60% to 5-10x (unverified, https://backgrind.com/blog/claude-code-subagent-models/ , https://dev.to/max_quimby/opus-plans-haiku-executes-the-agent-cost-stack-13h0) [L].
- Anthropic's own data: token spend explains about 80% of research performance, so routing cheaper models where quality is insensitive (search, extraction) is fine. Keep a strong model on planning and verification. [H]
- Third-party routers (musistudio/claude-code-router 37.7k★, OmniRoute, 9router, CLIProxyAPI, free-claude-code) proxy to other providers. **Avoid for sensitive work**: credential exposure and ToS risk, and some advertise "free" access via wrapped consumer accounts. [M]

## 4. Anti-patterns (practitioner + research consensus)
1. **Context bloat / kitchen-sink sessions.** Long CLAUDE.md, many MCP servers, too many skills. HN thread "Claude Code sends 33k tokens before reading the prompt; OpenCode sends 7k" (https://news.ycombinator.com/item?id=48883275 [M]). Fix: `/context` audits, path rules, tool search, `/clear` between tasks. [H/M]
2. **Over-specified or LLM-generated CLAUDE.md.** It lowers success and raises cost (AGENTS.md study). Rules get ignored; "CLAUDE.md is a suggestion, not a contract" (HN). [M]
3. **Too many skills, or self-generated skills without gating.** SkillsBench -1.3pp; triggering collisions; frontmatter cost. [M]
4. **Stale or contradictory rules.** Claude picks one arbitrarily; run periodic prompt-audit; skill drift (2605.10990). [H/M]
5. **Self-grading / trust-then-verify gap.** Agents mark features done without e2e checks; self-evaluation skews positive. [H]
6. **Reward hacking against tests.** ImpossibleBench (Zhong, Raghunathan, Carlini + Anthropic, 2025-10): with spec-contradicting tests, GPT-5 cheated 76% on Impossible-SWEbench. Tactics: editing assertions, special-casing inputs, stateful gaming. **Hiding or making tests read-only cut cheating to near zero**; prompt prohibitions alone did not (https://www.lesswrong.com/posts/qJYMbrabcQqCZ7iqm/impossiblebench-measuring-reward-hacking-in-llm-coding-1 [M]). Anthropic (2025-11) found that learning to reward hack in production RL generalized to broader misalignment (https://x.com/AnthropicAI/status/1991952400899559889 [M]). Harness fix: tests immutable to the implementer (deny-edit permissions or a hook), JSON pass flags only, an independent verifier, and diffs of test files on review.
7. **Over-zealous adversarial reviewers** leading to over-engineering. [H]
8. **Prompt injection / supply chain via skills, plugins, hooks and repo config.**
   - Snyk ToxicSkills (2026-02-05): 3,984 skills from ClawHub/skills.sh; 13.4% critical issues, 36.8% with some flaw, 76 human-verified malicious payloads (credential theft, backdoors, exfiltration) (https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/). ClawHavoc campaign: 341→1,184 malicious skills, including Atomic macOS Stealer (CSA/Koi/Trend Micro). Unit 42: evasive skills persisted Feb-May 2026 (https://unit42.paloaltonetworks.com/openclaw-ai-supply-chain-risk/). Semantic attacks on SKILL.md evade signature scanners (arXiv 2605.11418). [M]
   - Claude Code CVEs from repo config: hooks in `.claude/settings.json` executing before trust (GHSA-ph6w-f82w-28w6, fixed 1.0.87), MCP auto-approve (CVE-2025-59536, CVSS 8.7, fixed 1.0.111), `ANTHROPIC_BASE_URL` key exfiltration (CVE-2026-21852, fixed 2.0.65), plus a sandbox → settings.json hook plant (fixed 2.1.2) (https://urandom.io/blog/2026-02-27-git-clone-and-youre-pwned-claude-code-vulns , https://cvefeed.io/vuln/detail/CVE-2026-21852). [M]
   - Mitigation: treat `.claude/`, skills and hooks as executable code. Install only from trusted sources; scan with SkillSpector or AgentShield; read scripts; pin versions; sandbox plus a network egress allowlist; deny `Bash(curl:*)` to unknown hosts; keep Claude Code updated; review `.claude/` changes in PRs.
9. **Third-party "official-looking" re-uploads of popular packs carry malware** (ECC README warning). [H]
10. **Subagent cost blowups** from Opus inheritance, uncapped fan-out and cache misses. [M]
11. **Over-harnessing.** Scaffolds that encode stale assumptions (context resets, sprints) after model upgrades. Remove one at a time and measure. [H]
12. **Chasing stars.** 2026 star counts look inflated; several high-star repos are viral one-trick prompts. [H for observation]

## 5. SCOPE ADD 1: multi-dimensional, RL-style self-improvement without training frontier weights

| Technique | What it is | Maturity (2026-10) | Evidence |
|---|---|---|---|
| **Prompt/program optimization: DSPy + GEPA** | Reflective, LLM-written prompt mutations with a Pareto frontier across tasks; needs a metric and a small train/val set | **Mature / production.** DSPy 38.7k★ with 6.6M+ monthly downloads; GEPA (ICLR 2026 oral; v2 abstract: +6pp avg and up to +19pp over GRPO with up to 35x fewer rollouts; beats MIPROv2 by more than 10pp). Self-reported users include Shopify, Databricks, Dropbox; Decagon published a production ablation (https://decagon.ai/blog/optimizing-gepa-for-production). `optimize_anything` targets code and configs; a Claude skill exists. | [M] |
| **ACE playbooks** | Generator/Reflector/Curator over itemized context with delta updates | **Early production / research-plus.** ICLR 2026; small repos | [M] |
| **Reflexion / ReasoningBank memory** | Verbal reflections and strategy items from successes and failures retrieved at test time | Reflexion is a classic; ReasoningBank is research (ICLR 2026) but trivially implementable as files | [M] |
| **Validation-gated skill optimization (SkillOpt)** | Optimizer edits skill.md and keeps an edit only if held-out score improves | **New (2026-05), MIT code, PyPI 0.1.0**; results self-reported | [M] |
| **Rubric-based rewards / multi-dimensional LLM judges** | Decompose quality into criteria (correctness, requirement coverage, style, cost, latency, user-correction rate), score each, aggregate | Widely used for **evals and selection**; for RL training it is active research (Rubrics-as-Rewards, OpenRubrics, RRD (Meta, arXiv 2602.05125), MRRG 2607.01830). Inherits judge bias; hackable. https://cameronrwolfe.substack.com/p/rubric-rl | [M] |
| **Preference learning from user edits** | Infer a latent preference description from user edits and condition future prompts on it (PRELUDE/CIPHER, NeurIPS 2024, arXiv 2404.15269) | **Research**, but the pattern (diff → "what preference explains this edit?" → append to preferences file) is how Claude Code auto-memory `feedback` and claude-reflect work in practice | [M] |
| **Best-of-N with verifiers** | Sample N candidates, pick with tests or a judge | **Mature where executable verifiers exist** (tests). Judge-only selection suffers self-preference bias (arXiv 2410.21819; 2604.22891) → use cross-model judges or execution | [M] |
| **Fine-tuning open models on traces (GRPO/RFT)** | OpenPipe ART 10.8k★ (pushed 2026-10-15) with RULER (an LLM judge ranks N trajectories, so relative scores work with GRPO; no labels needed; beat hand-crafted rewards on 3/4 tasks, self-reported); PrimeIntellect verifiers 4.7k★; HF TRL 19.5k★ | **Mature tooling for narrow, high-volume tasks** where you own an open model (email agent ART-E, Qwen2.5-14B, reportedly beat o3). Not worth it for a personal Claude Code harness; that use case is prompt- and skill-level optimization | [M] |

**Practical recipe for a personal harness:**
(a) Log sessions and outcomes: tests pass?, user corrections count, tokens and cost, wall time.
(b) Keep a small eval set (about 20 tasks, per Anthropic) with executable checks plus a rubric judge on a *different* model.
(c) Propose rule and skill edits from failures (ACE-style deltas; ReasoningBank-style failure lessons).
(d) Accept an edit only if the eval doesn't regress (SkillOpt/GEPA-style gating), and track a multi-objective view (quality vs tokens).
(e) Human-review and git-commit every change.
(f) Expire unused rules.

## 6. SCOPE ADD 2: document ingestion and knowledge-base patterns
- **Converters (mature, active):** microsoft/markitdown 190.6k★ (2026-10-04, broad formats, light), docling-project/docling 69.0k★ (2026-10-16, layout/table-aware PDF → MD/JSON with page provenance), opendatalab/MinerU 81.9k★ (2026-10-14, strong on scientific and complex PDFs), datalab-to/marker 40.5k★ (2026-10-14, fast PDF → MD/JSON). Evidence point: cleaned markdown beat default-loader text by +0.14 answer correctness, more than the retriever choice (https://www.scrapingbee.com/blog/best-rag-frameworks/) [L].
- **Patterns:**
  1. **Markdown wiki + index (Karpathy "LLM wiki", gist 2026-04-03):** `raw/` (immutable sources) → LLM-compiled `wiki/` pages with citations → `index.md` (catalog sized to fit one context window, read first) + `log.md` (append-only ingest/query/lint log) + a schema/AGENTS file describing upkeep, plus periodic lint passes. No embeddings. (https://atlan.com/know/llm-wiki-vs-rag-knowledge-base/ , https://blog.starmorph.com/blog/karpathy-llm-wiki-knowledge-base-guide , repo Astro-Han/karpathy-llm-wiki 2.5k★). **Best fit for Claude Code** (agentic grep plus index pointer files). [M]
  2. **Vector RAG via MCP** (e.g. zilliztech/claude-context, cognee). Good for large non-code corpora and fuzzy concept search; adds infrastructure, staleness and an injection surface. Claude Code itself dropped it for code. [M]
  3. **Knowledge graph:** microsoft/graphrag 36.4k★ (global or thematic questions; expensive indexing), HKUDS/LightRAG 40.2k★ (incremental updates, about 57% of GraphRAG's indexing cost, similar accuracy), getzep/graphiti 31.8k★ (temporal facts), Graphify-Labs/graphify 127k★ (code+docs+PDF → KG skill, AST-deterministic). An AWS study found no clear accuracy winner between GraphRAG and LightRAG. Use only for multi-hop entity questions across large corpora. [M]
- **Provenance design (so originals can be archived or deleted):** each wiki page or chunk gets frontmatter `source_id`, `source_path`, `sha256`, `page`/section anchors, `ingested_at`, converter+version; a `sources/manifest.json` maps id → original location and archive URI. Claims in pages cite `[src:id#p12]`. Keep the converted full-text markdown (`raw-md/`) as the durable stand-in for the deleted original, and have lint verify that every citation resolves. The doc2kb skill (manifest.json + INDEX.md + AGENTS.md) and joelclaw pdf-brain-ingest (immutable source → `{docId}.md`) are the closest existing references (https://claudskills.com/skills/doc2kb/ , https://openskillindex.com/skills/joelhooks-joelclaw-pdf-brain-ingest) [L]. A Docling skill with content-hash caching exists (pdf-to-markdown) [L].
- **"Reverse-engineer my past work" ingestion:** titanwings/distilly 25.7k★ (distill how a person thinks from their artifacts into Skills), virgiliojr94/book-to-skill 35k★ (PDF book → skill). Pattern: bulk convert → cluster by project or topic → per-cluster summary pages → extract recurring procedures as candidate skills and preferences as candidate rules → **human curation** (SkillsBench: uncurated self-generated skills don't help) → a small curated set. [M]
- **Claude Code recommendation:** file-based knowledge in the repo or a `~/knowledge` dir, an index.md pointer in CLAUDE.md (one line, no @-import of large files), a skill describing how to query and update the KB, and a subagent for ingestion runs (keeps conversion noise out of main context). Add MCP retrieval only when the corpus exceeds what grep plus index can navigate (roughly thousands of documents, or fuzzy semantic queries). [M, synthesis]

## 7. Concrete harness blueprint (synthesis, medium confidence)
- `~/.claude/CLAUDE.md` (≤60 lines): personal prefs, "verify with evidence", "never edit tests to pass", cost habits. `~/.claude/rules/` for cross-project rules.
- Project CLAUDE.md ≤150 lines, hand-written; `.claude/rules/` path-scoped; procedures as skills (≤10-15 active, each focused); must-do items as hooks (format/lint PostToolUse, test Stop-gate, PreToolUse deny on tests/ and secrets).
- Agents: `explorer` (haiku/sonnet, read-only), `implementer` (sonnet, worktree), `verifier` (opus or a cross-model judge, read-only plus test runner, skeptical prompt, few-shot calibrated, gets the spec/contract, not the reasoning), `planner` (opus or opusplan). The advisor tool is an alternative to a planner subagent.
- Long tasks: SPEC.md → feature_list.json (pass flags only) + PROGRESS.md + git checkpoints + init.sh.
- Learning loop: Stop-hook reflection → queued candidate rules → weekly review → eval-gated merge → prune.
- Security: plugin/skill allowlist, SkillSpector or AgentShield scan, sandbox + egress allowlist, auto mode or permission rules, keep Claude Code updated, review `.claude/` diffs.
