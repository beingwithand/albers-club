# Index / pointer files: still best practice in 2026, and the harness index standard

Research note, 2026-10-16. The question: is "a small index file that says where things are, loaded or read first, with details opened on demand" still current best practice for Claude Code and LLM agents? If so, what one index standard should the whole `claude-harness` follow, and how does it fit Claude Code auto memory (`MEMORY.md`)?

## 0. Bottom line

1. **Yes, it is still best practice. In 2026 it moved from folk advice to built-in product behaviour.**
   - Claude Code's own memory is an index file. `MEMORY.md` is "an index of the memory directory", with "one line per memory". The first 200 lines or 25KB load every session, and topic files are read on demand.
   - Since July 2026 Claude Code enforces this at write time. The over-limit error tells Claude to "rewrite it to under 140 lines … keep one line per entry, move detail into topic files, and merge or drop stale entries" [H].
   - Every Claude Code docs page now opens with "Fetch the complete documentation index at: …/llms.txt. Use this file to discover all available pages before exploring further." [H]
2. **What changed in 2026:**
   - The tool now enforces the size limits.
   - Memory topic files carry a `modified` timestamp.
   - Frontmatter and HTML comments are stripped before the limit is measured.
   - Imitation markup in `MEMORY.md` is neutralized.
   - Evidence tightened what an index should contain:
     - **pointers plus purpose, not overviews or copies**: generic repo overviews in context files didn't help agents find code and added more than 20% cost (ETH Zurich, Feb 2026);
     - **small and always visible beats retrieved on request**: Vercel's 8KB docs index in AGENTS.md scored 100%, against 79% for skills;
     - **a large index is skipped or wasted**: a 150KB wiki catalog was never loaded by a capable agent (arXiv 2607.04576).
3. **The failure modes are known, and they are mechanical:**
   - an over-long index gets silently truncated (Claude Code fixed the signal for `MEMORY.md` only);
   - stale entries and relative dates;
   - pointers to renamed or deleted files;
   - duplicate indexes that drift apart;
   - indexes nobody reads because they sit 3 hops deep.
   All of these can be checked by a script. None of them needs a model.
4. **For the harness:**
   - Adopt one **INDEX standard (v1)** (§2).
   - **Generate** every index that has a machine source (frontmatter, manifest, filesystem, ontology). Hand-write only small routers.
   - Cap each index at **200 lines / 25KB**, with a **140-line target**, mirroring `MEMORY.md`.
   - Add **`scripts/index_check.py`**, which checks broken pointers, orphans, duplicates, size, staleness and privacy, and wire it into tests and `review-week`.
   - Lightly steer auto memory, but do not reformat it (§3).
5. **llms.txt** has low adoption on the web (about 9–10% of top sites) and almost no AI-crawler traffic. It is still a good **format** for agent-facing indexes: H1, a blockquote summary, H2 link lists, and an `Optional` section. Anthropic itself publishes one for agents. The harness should borrow the shape, not chase the SEO claims.

### 1.3 llms.txt standard and 2026 adoption
- **Format** (AnswerDotAI/llms-txt README, read) [H]:
  - "An H1 with the name of the project or site. This is the only required section".
  - Then a blockquote summary.
  - Then free-text detail.
  - Then H2 "file lists" of `[name](url): notes`.
  - The `Optional` section holds "links an agent can skip when a shorter context is needed".
- **Adoption** [M]:
  - About 8.7% of the Tranco top 1,000 (15.8% of reachable sites), June 2026, from Rankability.
  - About 10.1% of roughly 300k domains, from SE Ranking.
  - 28% of Ahrefs customers, a sample skewed to technical sites.
  - Shopify's 78% comes from a platform default.
  - Files grew 8.8× from June 2025 to May 2026, per Originality.
- **Usage** [M]:
  - 97% of files show no AI-crawler request.
  - No correlation was found between having the file and LLM citations.
  - About 15.7% of sites serve HTML at `/llms.txt`.
- **Reading:** the web/SEO case is weak. The **agent-tooling** case, where the agent fetches docs while it works, is where Anthropic and others use it, and that is the harness's situation.

### 1.5 Measurements

| Study | Finding | Relevance |
|---|---|---|
| Gloaguen et al., ETH Zurich, arXiv 2602.11988 (Feb 2026) [M] | Context files "do not generally improve task success rates, while increasing inference cost by over 20%". LLM-generated files were the only condition that lowered success. Repo overviews didn't help agents find relevant code. Files help most for **non-standard practices**. | An index must carry **what the filename and grep can't**: purpose, status, freshness, where the source lives. It should not narrate the structure. Generated **from structured metadata** ≠ "LLM-generated overview prose". |
| Vercel, "AGENTS.md outperforms skills" (Jan 2026) [M] | An 8KB compressed docs index embedded in AGENTS.md (cut down from about 40KB) reached a 100% pass rate. Skills reached 53% by default and 79% with explicit instructions. In 56% of cases the skill was never invoked. | A **small always-visible router** beats hoping the agent goes to look. Keep the router in a re-injected file, and keep it small. |
| arXiv 2607.04576, "Progressive Disclosure for LLM-Maintained Wiki KBs", preregistered (Jul 2026) [M] | 709-page wiki. Retrofitting away from a ~150KB catalog cut cost by about ⅓ (self-routing agent) and 58% (forced catalog preload), with quality inside the preregistered margin. But the judge–human agreement gate failed (κ = 0.23 vs 0.60). A capable agent **never loaded the big index**: the savings came from more targeted access (fewer pages cited, fewer tool turns). | A 150KB index is dead weight. Use **hierarchical, small indexes** that are cheap enough to actually read. |
| Cochran, arXiv 2605.18490 (May 2026) [M] | An LLM-compiled wiki (index-navigated) beat single-round RAG on cross-paper synthesis (weakly), but used about **21× more tokens per query**. | Index navigation is not free at query time. Keep indexes terse and support search as the fallback (`retrieval_strategies.md`). |
| McMillan, arXiv 2605.10039 (May 2026), 1,650 Claude Code sessions [M] | File size, position, architecture and conflicts had **no detectable effect** on adherence to a trivial instruction. Compliance fell about 5.6% (odds) per extra function in a session. | Don't over-engineer index formatting for "adherence". Freshness, correctness and brevity matter more. Re-read the index after long stretches or compaction. |
| Practitioner topic index [L] | Retrieval fell from about 24.5k to about 4.5k tokens (5–6×). | Plausible order of magnitude. No method published. |

**Net:**
- Pointer indexes reliably cut tokens when they are **small and hierarchical**.
- Big catalogs get skipped.
- Generic overviews cost more than they help.
- The quality gains are real but not well measured.
- The harness should measure them itself (§2.9).

## 2. Harness INDEX standard (v1)

Proposed home: `claude-harness/docs/INDEX_STANDARD.md`. The checker is `scripts/index_check.py`. This section is the spec.

### 2.1 Principles
1. **An index is a map, not a fence.** It says what is where, why it matters, how fresh it is, and where the source of truth lives. Search (Grep/Glob, later `recall`) remains the fallback.
2. **Carry only what isn't obvious.** That means purpose, status, date and source pointer. No architecture narration, no copied content.
3. **One index per scope. Never two indexes listing the same items.**
4. **Generated where a machine source exists. Hand-written only for routers and curation.**
5. **Small, head-first, at most 2 hops** from an always-loaded router to any leaf.

### 2.2 Where index files must exist

| Scope | Index file | Generated or hand-written | Writer / owner | Notes |
|---|---|---|---|---|
| Harness repo root | `README.md` § "What's inside" (router, ≤40 lines) → `docs/INDEX.md` | Router hand-written; map **generated** | `scripts/harness_index.py --write` (exists) | `docs/INDEX.md` already covers `agents/`, `skills/`, `hooks/`, `scripts/`, `rubrics/`, `docs/` and the ontology. So **no per-folder `skills/INDEX.md` or `agents/INDEX.md`**, which would be duplicates. |
| Each skill folder | `SKILL.md` `## Additional resources` section | Hand-written | skill author | Links one level deep. Any reference file over 100 lines gets a TOC. |
| Each project (`<area>/<project>/`) | `CLAUDE.md` `## Map` section (≤15 lines, from the template) | Template plus hand edits | `skills/new-project` | Always loaded and re-injected after compaction, so this is the project's router. It points to `HANDOFF.md`, `PROGRESS.md`, `decisions.md`, `knowledge/INDEX.md`, `assets/assets.yaml`, `log/`, `deliverables/`, using backticked paths with no `@`. |
| Each knowledge base (`knowledge/`, incl. `$HARNESS_DATA/backcatalog/knowledge/`) | `knowledge/INDEX.md` | **Generated** | `scripts/kb.py index`, the **only** writer | Intake step 4 changes from "add a line" to "run `kb.py index`". |
| `$HARNESS_DATA` root | `$HARNESS_DATA/INDEX.md` | **Generated** | new `index_check.py --write harness-data` (or a `schema_check.py --stores` extension) | One line per store from `ontology.yaml` `store:` blocks, plus record count and last write. **No record content.** The vault appears only as "local only, see the Mac". |
| Sub-stores with many files (`evals/results/<area>/`, `labels/`, `research/`) | none if the files are date/id-named; the jsonl ledgers *are* the index (`research/ledger.jsonl`) | — | — | Chronological, sortable filenames are already an index. Don't add one. |
| Message vault `~/msg-vault/` (Mac only) | `~/msg-vault/INDEX.md` | **Generated, local only** | vault ingest script | Structure only: source dirs, file names, record counts, date ranges, cursor status. **Never** subjects, names, addresses, excerpts or thread titles. Never committed or synced. Readable only by local agents. |
| Research notes (`research_notes/`, and each topic folder with >7 notes or subfolders, e.g. `research_notes/Claude harness/`) | `INDEX.md` per folder | **Generated** | `index_check.py --write research` | One line per note, from its H1, its "Research note, <date>" line and its first bottom-line bullet. Status `current`, `superseded → <path>` or `review` (older than 180 days on a fast-moving topic). |

**When a new folder needs an index:** it holds knowledge (not code or raw data), and either has more than 7 items, has subfolders, or is a store root. Otherwise the filenames are enough, given the descriptive-name rule.

**Filename:** `INDEX.md` (uppercase) everywhere.
- Migrate `knowledge/index.md` → `knowledge/INDEX.md`. On macOS (a case-insensitive filesystem) use `git mv -f`.
- The checker accepts `index.md` with a deprecation warning for one release.
- This also fixes the existing mismatch: `BLUEPRINT.md` §4.11 says `knowledge/INDEX.md`, while the template, `kb.py`, intake and the project CLAUDE.md say `knowledge/index.md`.

### 2.3 Required format

The format is llms.txt-compatible, so any llms.txt-aware tool can read it.

```markdown
---
index: v1
scope: knowledge base of <project>        # what this index covers
generated_by: scripts/kb.py index          # or "hand"
updated: 2026-10-16                        # ISO date of last regeneration / edit
owner: skills/intake                       # who keeps it current
---
# Knowledge index: <project>
> One sentence: what is in scope, and what is NOT (e.g. "client text lives in raw/; vault not indexed here").

## Read first
- [wiki/brief.md](wiki/brief.md) — Client brief: goals, deadline, register — active · 2026-10-12 — src: raw/1a2b3c4d_brief.pdf#p.1

## Contract
- [wiki/fees.md](wiki/fees.md) — Fee schedule and late-delivery penalties — active · 2026-10-12 — src: raw/1a2b3c4d_contract.pdf#p.12

## Optional
- [wiki/background.md](wiki/background.md) — Company history, not needed for the translation — active · 2026-10-12 — src: raw/9f8e7d6c_about.pdf
```

**Entry line grammar.** There is one line per item, split on ` — ` (space, em dash, space):

```
- [<path>](<path>) — <purpose> — <status> · <updated> — <pointer>
```

- **path**: relative to the index file, forward slashes, and a markdown link so it is clickable and checkable. A folder entry ends with `/` and points to that folder's `INDEX.md`.
- **purpose**: 4–15 words. Say what it answers or when to open it, not how it works. It must not contain ` — `. It comes from the item's own frontmatter `summary:` or `description:` when generated, so the item stays the single source of truth.
- **status**: one of `active`, `draft`, `planned`, `review`, `stale`, `superseded → <path>`, `archived`, `generated`.
- **updated**: an absolute `YYYY-MM-DD`. For generated indexes it is the item's last **git commit date** (mtime when not in git, e.g. the vault). Relative dates are never allowed.
- **pointer**: where the evidence or original lives, as one of:
  - `src: raw/<sha8>_<name>#p.N`
  - `drive: <url>`
  - `id: D-… / evt_… / rn_…`
  - `vault: <source>/<file>` (local only)
  - `-` when the path is itself the source.

**Sections:**
- H2 by category.
- `## Read first`: at most 5 lines, and always first.
- `## Optional`: last; agents skip it unless asked.
- No prose paragraphs beyond the blockquote. A hand-written index may have one `## Notes` block of 5 lines or fewer.

**Hybrid files** (hand-written router plus generated list) put the generated part between `<!-- BEGIN GENERATED: <tool> -->` and `<!-- END GENERATED -->`. Generators rewrite only that block, and hand-written lines outside it are preserved. HTML comments and frontmatter don't count toward the size cap, which matches Claude Code's measurement.

### 2.4 Size caps (mirroring `MEMORY.md`)

| Kind | Target | Warn | Error |
|---|---|---|---|
| Any `INDEX.md` (loaded content, excluding frontmatter and comments) | ≤140 lines | >140 lines | >200 lines **or** >25KB |
| Always-loaded routers (project CLAUDE.md `## Map`, README router) | ≤15 lines (project), ≤40 (README) | over target | — |
| Entry line | ≤160 chars | >200 chars | >300 chars |
| `## Read first` | ≤5 lines | >5 | — |
| Total always-loaded index text per session (router plus MEMORY.md) | ≤3k tokens [est] | >5k | — |

**Over the cap → split, don't truncate.**
- Promote the biggest H2 section into a sub-folder index, so the parent gets one line pointing to `<folder>/INDEX.md`.
- The maximum depth stays 2 hops from a router to a leaf: router → folder index → item, or router → index → sub-index → item for at most one store (the knowledge wiki at over 200 pages).
- At about 300 or more items in one scope, the index stops being the primary navigator. Use search (`recall`/FTS from `retrieval_strategies.md`) and keep the index as a category map (the Karpathy threshold, and 2607.04576).

### 2.5 Generated vs hand-written

| Rule | Why |
|---|---|
| If a machine source exists (frontmatter, `manifest.json`, `ontology.yaml`, filesystem, jsonl ledger), the index is **generated** and has exactly one writer. | Derived views can't drift. JSON/YAML sources resist accidental model edits (Anthropic harness post). ETH found free-form LLM-written context files hurt. |
| Generated indexes are never hand-edited. Fix the source (frontmatter `summary:`), then regenerate. | Hand edits get overwritten (today `kb.py index` would silently erase intake's hand-added lines). |
| Hand-written is allowed for routers, `## Read first` curation and `## Notes`. | Curation of what matters needs judgment. |
| Model-written indexes (MEMORY.md) follow the native profile and are checked, never auto-rewritten by scripts. | Claude Code owns that format. Scripts propose, the user or Claude edits. |

### 2.6 Freshness and staleness rules
1. **Regenerate on write.** Every writer script (`kb.py`, the research-note writer, the ingest) regenerates its index in the same step. It is a postcondition in `docs/VERIFICATION.md` terms: "index regenerated, `index_check --scope <x>` clean".
2. **Stale generated index** means the committed file differs from a fresh regeneration (`--check` dry run). That is an **error** in tests.
3. **Stale hand entry** means the entry's `updated` is older than the target's last commit. That is a **warning**, and the index `updated` must be ≥ the newest entry date.
4. **Stale content**, which is not about the pointer:
   - research notes older than 180 days on fast-moving topics → `review` (per global CLAUDE.md "flag claims … more than ~6 months old");
   - MEMORY.md / agent-memory entries whose topic file `modified` is older than 90 days → listed in `review-week` for confirm/merge/drop.
5. **Supersession.**
   - Hand indexes mark `superseded → <path>` instead of deleting the line for 30 days, then drop it.
   - Generated indexes take the status from the item's frontmatter `status:`/`superseded_by:`.
6. **No relative dates anywhere in an index** ("yesterday", "last week", "recently"). The lint rejects them.

### 2.7 How agents use indexes (goes into global CLAUDE.md invariant 3 and the orchestrator)
1. **Start at the router that is already in context** (project CLAUDE.md `## Map`, MEMORY.md). Open the scope's `INDEX.md` before opening any file in that scope.
2. **Choose by purpose and status.** Skip `## Optional`, `archived` and `superseded` unless the task needs them. Prefer `## Read first`.
3. **Open only what's needed.** For any leaf over 100 lines, read its TOC/headings first.
4. **Index miss, so search.** If the index lacks what you need, use Grep/Glob. Then fix the source frontmatter, or log an `index_miss` event (`intent`, `situation`: what was looked for, where it was found). This is the learning-loop signal (principle 22).
5. **Broken pointer, so stop trusting that entry.** Log `index_broken` and run `index_check.py --scope <x>`. Never guess the replacement path silently.
6. **Never `@`-import an index** into CLAUDE.md, because imports load fully at launch. Reference it with a backticked path.
7. **Delegation.** Subagents don't see the main auto memory or the conversation, so the delegation prompt names the index path(s) to read first, e.g. "Read `knowledge/INDEX.md` first."
8. **After compaction or about 30+ tool turns,** re-read the relevant index rather than trusting the summary (McMillan's within-session decay; only 5 recent files are re-read after compaction).
9. **Writing** a new knowledge file means updating its index in the same step (regenerate, or add the hand line). A file that isn't indexed doesn't exist, for the next session.

### 2.8 Automatic pointer-integrity check: `scripts/index_check.py`

Stdlib only, run with `python3 -I`. The modes are `--check` (default, exit 1 on errors), `--write <scope>`, `--scope repo|project <path>|harness-data|research|memory|vault`, and `--json`.

| Code | Check | Severity |
|---|---|---|
| I1 broken | every `[..](path)` resolves relative to the index. `#p.N` / `#heading` anchors resolve when the target is md (page anchors `<!-- p.N -->`, headings). `src: raw/…` exists. | error |
| I2 orphan | every knowledge file in scope is listed in exactly one index (`.indexignore` allowlist). MEMORY.md: topic files not linked. | error (generated scopes) / warn (hand, memory) |
| I3 duplicate | the same target in two indexes, or twice in one | error |
| I4 size | lines/bytes after stripping frontmatter and HTML comments, plus line length (§2.4) | warn >140 lines, error >200 lines / 25KB |
| I5 format | the line parses into 4 fields, status in the vocabulary, ISO date, no ` — ` inside purpose, frontmatter `index: v1` | error |
| I6 stale | generated: regenerate-and-diff. hand: entry date < target's last commit. index `updated` < newest entry. relative-date regex. | error / warn |
| I7 depth | the BFS from routers reaches every index in ≤2 hops (≤3 for one declared store) | warn |
| I8 privacy | repo and harness-data indexes contain no vault paths except the root pointer, and no emails, phone numbers or Korean RRN patterns (regex). The vault index is not git-tracked (`git ls-files`) and the vault has no remote. | error |
| I9 memory | MEMORY.md and agent-memory indexes: size (I4), I1 for links, I2 for orphan topic files, relative dates, and lines that look like instructions from content (poisoning heuristic, `docs/SECURITY.md`) | warn only. **Reports, never edits.** |

**Wiring:**
- **Tests.** `tests/test_index_check.py` covers fixtures for each code. `tests/test_kb.py` asserts that `kb.py index` produces a v1-valid file.
- **Generators.** `kb.py index`, `harness_index.py --write` and the research/harness-data writers call `index_check --scope` afterwards (postcondition).
- **`review-week`** runs `--check` over all scopes, including `memory` and, on the Mac, `vault`, and lists I6/I9 review items for the user.
- **`learning/contracts.yaml`** gets an entry for `script:scripts/index_check.py` (signals: `index_miss`, `index_broken` events; metric: miss rate per week).
- **Optional:** the SessionStart (compact/clear) reinject hook adds one line, "index_check: N broken pointers in <scope>", when the last run had errors. Never the full report.

**Also extend `kb.py`:**
- `index` writes the v1 format: grouped by frontmatter `category`, with status from `status` (default `active`), the date from the git commit date, and the pointer `src: raw/<sha8>…#p.<first page>`.
- `lint` adds I1–I3 and I6 for the knowledge scope.
- The current separator `topic: summary: path` breaks on summaries that contain colons, and it has no status, date or source.

### 2.9 Measure it (cheap, uses existing eval machinery)
- **Gold set.** Add 10–20 "where is X / what does the project say about Y" tasks per area to `evals/research` or a new `evals/retrieval` area. Run each with and without the index, using the same model (`self-eval`).
- **Metrics:** answer correct (verifier); tokens in; tool turns; files opened; `index_miss` count.
- **Accept the standard** if tokens fall by at least 30% with no loss in correctness [est target, based on the ~⅓ saving in 2607.04576].

## 3. Fit with Claude Code auto memory

**MEMORY.md is already an index under this standard.** It is the "native profile":
- One line per memory, of the form `- [Title](topic_file.md) — one-line hook`.
- At most 200 lines / 25KB, enforced by Claude Code, with a 140-line rewrite target.
- Freshness lives in each topic file's frontmatter `modified` (ISO, written by Claude Code v2.1.214+). It is **not duplicated** into the index line, because duplicated dates drift.
- `status` and `pointer` fields are optional in this profile.
- `index_check.py --scope memory` checks it (I1, I2, I4, I9) but never rewrites it.

**Should we steer auto memory to follow the standard? Lightly, yes.** The steering covers *what goes where* and *hygiene*, not a reformat. Claude Code already reminds Claude, in its own words, to keep one line per entry, so forcing the 4-field line would fight the built-in prompt and gain little.

Add 5 lines to `global/CLAUDE.md` (user scope; under the 50-line file, still far from 200):

```markdown
## Memory hygiene
- Auto memory (MEMORY.md) is an index: one line per note, `- [Title](file.md) — when it matters`; details in topic files. Absolute dates only.
- Auto memory is machine-local and unsynced: keep only user/feedback/reference notes there. Project facts, decisions and knowledge go to the project's files (decisions.md, knowledge/, PROGRESS.md), which are synced and indexed.
- Never put client, vault or third-party text in memory; point to it by id instead.
- If a memory points to a path that no longer exists, fix or delete the memory in the same turn.
```

**Why:**
- Auto memory lives in `~/.claude/projects/<p>/memory/`, which is **not synced** (`STORAGE.md` "home" root, `settings.README.md`). That conflicts with principle 12, "nothing lives in only one place", for anything important.
- The docs say auto memory skips what is derivable from code or already in CLAUDE.md. The harness adds: "or already in a harness store".

**Subagent memories** (12 agents declare `memory:`):
- Add a 2-line block to each agent body, as the docs recommend: "Keep your MEMORY.md as an index: one line per note, `- [Title](file.md) — hook`; put detail in topic files; absolute dates; consult it before starting and update it after finishing."
- `memory: project` dirs (`.claude/agent-memory/`) are git-tracked in the project, so they are covered by I1/I2/I8 in `--scope project`.
- `memory: user` dirs (`~/.claude/agent-memory/`) are covered by `--scope memory`.

**Backup option** (decision for the user; not recommended by default):
- `autoMemoryDirectory` could point memory into `$HARNESS_DATA`, so it would be synced. But it is one directory for whatever settings scope sets it. At user scope it would merge all projects' memories, and a project-scope setting is subject to workspace trust and `blockReadsOutsideWorkingDirectories`.
- Safer: `scripts/autocommit_data.sh` mirrors `~/.claude/projects/*/memory/` to `$HARNESS_DATA/memory-mirror/<host>/` after an I8 privacy scan.
- Either way, `patterns.py --auto-memory` keeps reading `feedback` notes as evidence (`docs/PATTERNS.md`).

**After compaction,** auto memory is re-injected from disk. That makes MEMORY.md, together with the project CLAUDE.md `## Map`, the two reliable places to hold a pointer to deeper indexes. Folder indexes that were read earlier may be summarized away.
