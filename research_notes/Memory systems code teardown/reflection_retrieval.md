## Q1. Concrete formulas, thresholds and prompts (scoring, reflection, linking, retrieval)

### Takeaway
Generative Agents scores every memory as `0.5·recency + 3·relevance + 2·importance` (each min-max normalized to [0,1]; recency = 0.99^rank; importance = LLM 1–10 "poignancy"), and reflects when summed poignancy of new events reaches 150. A-MEM uses no scoring formula: plain cosine top-k (k=5) over MiniLM embeddings, with an LLM call per new note that decides links and rewrites neighbours' context/tags. Khoj is classic RAG: 256-token chunks, gte-small bi-encoder with cosine distance cutoff 0.18, top-10, cross-encoder rerank. Memobase uses no per-memory score: it keeps a topic/subtopic profile merged by LLM, plus event "gists" fetched by cosine similarity > 0.2 within 180 days.

### Cited Findings

**Generative Agents: retrieval score** (`cognitive_modules/retrieve.py`)
- Hyperparameters: `recency_w = 1`, `relevance_w = 1`, `importance_w = 1`, `recency_decay = 0.99`, `importance_trigger_max = 150` — [GA memory_structures/scratch.py#L57-L63](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/memory_structures/scratch.py#L57)
- The final score hard-codes extra global weights `gw = [0.5, 3, 2]`: `master_out[key] = recency_w*recency*gw[0] + relevance_w*relevance*gw[1] + importance_w*importance*gw[2]`. So in practice the weights are recency 0.5, relevance 3, importance 2. The paper's equal weighting is overridden here. — [GA retrieve.py#L244-L249](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/retrieve.py#L244)
- Each component is min-max normalized to [0,1] with `normalize_dict_floats(d, 0, 1)`. If all values are equal, each one is set to `(max-min)/2` = 0.5. — [GA retrieve.py#L93-L104, L231-L236](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/retrieve.py#L231)
- Recency comes from rank, not wall-clock time: candidates (all `seq_event + seq_thought`, excluding "idle") are sorted ascending by `last_accessed`, then `recency_vals = [recency_decay ** i for i in range(1, len(nodes)+1)]` is assigned in that order. — [GA retrieve.py#L145-L152, L224-L228](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/retrieve.py#L145)
- Relevance = cosine(node embedding, focal-point embedding). Embeddings come from OpenAI `text-embedding-ada-002`. — [GA retrieve.py#L189-L196](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/retrieve.py#L189); [GA prompt_template/gpt_structure.py#L276-L281](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/prompt_template/gpt_structure.py#L276)
- Importance = stored `node.poignancy`. Top `n_count` (default 30) are returned, and **retrieved nodes get `last_accessed = curr_time`**, so retrieval itself refreshes recency. — [GA retrieve.py#L168-L172, L199, L262-L269](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/retrieve.py#L262)
- Callers pick `n_count` per use: 30 (default, planning/reflection); conversation uses 50 to summarize the relationship, then 25 or 15 for topic ideas. — [GA cognitive_modules/converse.py#L92-L96, L132-L167](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/converse.py#L92)
- Importance prompt, used verbatim (v3_ChatGPT/poignancy_event_v1.txt): *"Here is a brief description of !<INPUT 0>!. !<INPUT 1>! On the scale of 1 to 10, where 1 is purely mundane (e.g., brushing teeth, making bed) and 10 is extremely poignant (e.g., a break up, college acceptance), rate the likely poignancy of the following event for !<INPUT 2>!. Event: !<INPUT 3>! Rate (return a number between 1 to 10):"*. Separate variants exist for thoughts and chats. Events containing "is idle" are hard-coded to 1 with no LLM call. — [GA prompt_template/v3_ChatGPT/poignancy_event_v1.txt](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/prompt_template/v3_ChatGPT/poignancy_event_v1.txt); [GA run_gpt_prompt.py#L1885, L1956, L2028](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/prompt_template/run_gpt_prompt.py#L1885); [GA reflect.py#L73-L83](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/reflect.py#L73)

**Generative Agents: reflection**
- Trigger: each perceived event decrements a counter, `importance_trigger_curr -= event_poignancy; importance_ele_n += 1`. Reflection fires when `importance_trigger_curr <= 0`, i.e. when summed poignancy since the last reflection reaches ≥150. After reflecting, the counter resets to 150 and `importance_ele_n` to 0. — [GA perceive.py#L178-L179](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/perceive.py#L178); [GA reflect.py#L152-L169](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/reflect.py#L152)
- Step 1, focal points: take the last `importance_ele_n` memories (exactly those since the last reflection), sorted by last_accessed, and ask for 3 questions: *"[statements] Given only the information above, what are 3 most salient high-level questions we can answer about the subjects grounded in the statements?"* — [GA reflect.py#L21-L35](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/reflect.py#L21); [GA v3_ChatGPT/generate_focal_pt_v1.txt](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/prompt_template/v3_ChatGPT/generate_focal_pt_v1.txt)
- Step 2: `new_retrieve` (top 30) runs for each focal point. Step 3, insights: the nodes are numbered and the prompt asks *"Input: 0. … 1. … What 5 high-level insights can you infer from the above statements? (example format: insight (because of 1, 5, 3))"* (text-davinci-003, temp 0.5). The cited indices become `evidence` node ids (`filling`). — [GA reflect.py#L38-L55, L110-L132](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/reflect.py#L110); [GA v2/insight_and_evidence_v1.txt](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/prompt_template/v2/insight_and_evidence_v1.txt); [GA run_gpt_prompt.py#L2170-L2178](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/prompt_template/run_gpt_prompt.py#L2170)
- Each insight is stored as a "thought" node with: an SPO triple (from another LLM call), keywords = {s,p,o}, its own poignancy score (another LLM call), an embedding, `expiration = now + 30 days`, and evidence links. Reflections can therefore cite earlier reflections, which builds a reflection tree. — [GA reflect.py#L122-L132](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/reflect.py#L122)
- After each conversation ends, two extra thoughts are written: a "planning thought" and a "memo" about the conversation. Both cite the chat node as evidence. — [GA reflect.py#L190-L244](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/reflect.py#L190)

- Note schema: `content, id(uuid4), keywords[], links[], context="General", category="Uncategorized", tags[], timestamp(YYYYMMDDHHMM), last_accessed, retrieval_count, evolution_history[]`. — [AM memory_system.py#L25-L82](https://github.com/agiresearch/A-mem/blob/ceffb860f0712bbae97b184d440df62bc910ca8d/agentic_memory/memory_system.py#L25)

**A-MEM: link generation and memory evolution (a single combined LLM call)**
- On every `add_note` (except the first), `process_memory` takes the top-5 cosine neighbours, formats them as `memory index:{i}\ttalk start time:…\tmemory content:…\tmemory context:…\tmemory keywords:…\tmemory tags:…`, and sends the evolution prompt: *"You are an AI memory evolution agent … Based on this information, determine: 1. Should this memory be evolved? … 2. What specific actions should be taken (strengthen, update_neighbor)? 2.1 If choose to strengthen the connection, which memory should it be connected to? Can you give the updated tags of this memory? 2.2 If choose to update_neighbor, you can update the context and tags of these memories … Generate the new context and tags in the sequential order of the input neighbors."* Output: `{should_evolve, actions, suggested_connections, tags_to_update, new_context_neighborhood, new_tags_neighborhood}`. — [AM memory_system.py#L126-L157, L288-L313, L590-L700](https://github.com/agiresearch/A-mem/blob/ceffb860f0712bbae97b184d440df62bc910ca8d/agentic_memory/memory_system.py#L590)
- Effects: "strengthen" does `note.links.extend(suggested_connections); note.tags = tags_to_update`. "update_neighbor" overwrites each neighbour's `tags` and `context` (never its content). Each time `should_evolve` is true, `evo_cnt` increments, and every `evo_threshold` (100) evolutions `consolidate_memories()` rebuilds the vector index. — [AM memory_system.py#L233-L286](https://github.com/agiresearch/A-mem/blob/ceffb860f0712bbae97b184d440df62bc910ca8d/agentic_memory/memory_system.py#L233)
- Retrieval (`search_agentic`): Chroma top-k, then one-hop expansion over `links` (at most k neighbours total, flagged `is_neighbor: True`), truncated to k. — [AM memory_system.py#L509-L588](https://github.com/agiresearch/A-mem/blob/ceffb860f0712bbae97b184d440df62bc910ca8d/agentic_memory/memory_system.py#L509)
- Research repo: `HybridRetriever` exists with `hybrid = alpha·BM25_norm + (1-alpha)·cosine` and `alpha = 0.5`, but `AgenticMemorySystem` actually uses `SimpleEmbeddingRetriever` (pure cosine), and the BM25 call is commented out in `find_related_memories`. — [AMR memory_layer.py#L403-L552, L678, L859-L866](https://github.com/WujiangXu/A-mem/blob/0c8039f28fdcc08189a23c07a3437d9d2482f9c2/memory_layer.py#L529)
- Research repo QA pipeline: an LLM first turns the question into keywords, then `find_related_memories_raw(keywords, k=retrieve_k)` (default 10) concatenates each hit and its linked notes as `talk start time:… memory content:… memory context:… memory keywords:… memory tags:…`. — [AMR test_advanced.py#L95-L134, L417](https://github.com/WujiangXu/A-mem/blob/0c8039f28fdcc08189a23c07a3437d9d2482f9c2/test_advanced.py#L127); [AMR memory_layer.py#L877-L897](https://github.com/WujiangXu/A-mem/blob/0c8039f28fdcc08189a23c07a3437d9d2482f9c2/memory_layer.py#L877)

### Inferences
- For Relic, the GA formula transfers directly: `score = 0.5·rec + 3·rel + 2·imp`, each min-max normalized over the candidate set. Because of min-max normalization, the weights are relative to the spread inside the candidate set, so the result changes with how many and which candidates are scored. A fixed-range variant would be more stable (e.g. imp/10, cosine as is, recency = exp(-Δt/τ) on wall-clock hours).
- The GA reflection trigger (Σ poignancy ≥ 150) works out to roughly 15–40 events at typical scores of 4–10. For a personal app, this maps naturally to "reflect after N meaningful entries or nightly, whichever comes first".
- The A-MEM evolution is one LLM call per inserted note, plus a construction call. Note: in the packaged agiresearch version, `add_note` never calls `analyze_content` (grep shows it is defined at L159 and only used there), so keywords/context/tags are empty ("General") unless the caller passes them. The research repo calls it inside `MemoryNote.__init__` (AMR memory_layer.py#L281-L286).

### Gaps
- GA's paper text (arXiv) could not be fetched here (blocked), so I could not cross-check the paper's stated weights against the `gw=[0.5,3,2]` in code. The code is authoritative for what actually ran.

## Q2. How user profiles are structured and updated

### Takeaway
There are three distinct designs. Memobase keeps a **fixed-schema topic→subtopic→memo slot table**, updated by an extract → per-slot merge (APPEND/UPDATE/ABORT) → reorganize pipeline that runs in batches when a 1024-token buffer fills. Khoj keeps a **flat list of atomic first-person facts** with create/delete-only updates after each chat. Supermemory exposes **static vs dynamic profile lists** plus versioned `Updates/Extends/Derives` relations, but the engine that builds them is closed. A-MEM and GA have no "profile". GA's closest equivalent is the `currently` status string rewritten daily from retrieval.

### Cited Findings

**Memobase (most complete, open)**
- Default profile schema (`CANDIDATE_PROFILE_TOPICS`): `basic_info{Name, Age(int), Gender, birth_date, nationality, ethnicity, language_spoken}`, `contact_info{email, phone, city, country}`, `education{school, degree, major}`, `demographics{marital_status, number_of_children, household_income}`, `work{company, title, working_industry, previous_projects, work_skills}`, `interest{books, movies, music, foods, sports}`, `psychological{personality, values, beliefs, motivations, goals}`, `life_event{marriage, relocation, retirement}`. It can be overridden or extended per project via `overwrite_user_profiles` / `additional_user_profiles`. — [MB prompts/user_profile_topics.py#L9-L79](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/prompts/user_profile_topics.py#L9); [MB env.py#L112-L117](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/env.py#L112)
- Pipeline (`process_blobs`): load the project config and existing profiles → `entry_chat_summary` (chats → dated memo) → in parallel, the profile path (extract → merge → organize) and event tagging → `handle_session_event` → `handle_user_profile_db`. — [MB controllers/modal/chat/__init__.py](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/controllers/modal/chat/__init__.py)
- Step 1, entry summary: *"You are a expert of logging personal info, schedule, events from chats … If the user event/schedule has specific mention time or event happen time. Convert the event date info … e.g. `[2024/04/30] user: I bought a new car yesterday!` → `user bought a new car. [mention 2024/04/30, buy car in 2024/04/29]`"*. This keeps "mentioned" and "occurred" dates separate. — [MB prompts/summary_entry_chats.py#L6-L40](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/prompts/summary_entry_chats.py#L6)
- Step 2, extraction: *"You are a professional psychologist … extract the important profiles of user in structured format … not only extract the information that's explicitly stated, but also infer what's implied"*. Output is one line per fact, `- TOPIC::SUB_TOPIC::MEMO` (`llm_tab_separator="::"`), after a `THINKING --- ` section. Rules include "Use specific dates when possible, never use relative dates" and "Place all content related to this topic/sub_topic in one element". A `strict_mode` forbids topics outside the schema. — [MB prompts/extract_profile.py](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/prompts/extract_profile.py)

Outputs are `- APPEND::APPEND`, `- UPDATE::[UPDATED_MEMO]` or `- ABORT::ABORT`. Constraints: "Ensure the final memo does not exceed 5 sentences", "Never make up content", "Preserve time annotations from both old and new memos (e.g.: XXX[mentioned on 2025/05/05, occurred in 2022])". — [MB prompts/merge_profile.py#L9-L74](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/prompts/merge_profile.py#L9)
- Step 4, organize: if a topic has more than `max_profile_subtopics` (15) subtopics, an LLM regroups them into at most `15//2+1 = 8` subtopics. A `re_summary` step also shrinks memos larger than `max_pre_profile_token_size` (128 tokens). — [MB controllers/modal/chat/organize.py#L31, L97-L122](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/controllers/modal/chat/organize.py#L31); [MB env.py#L88-L89](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/env.py#L88)

**Khoj (flat fact list, "Muninn")**
- `UserMemory` model: `user, agent(nullable), embeddings(VectorField), raw(Text), search_model`, plus created/updated timestamps. — [KH database/models/__init__.py#L855-L864](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/database/models/__init__.py#L855)
- Update prompt: *"You are Muninn, the user's memory manager … You can take two kinds of action: 1. Create new facts 2. Delete existing facts … You cannot update existing facts directly, instead create new facts and delete related existing ones to update them … Each fact should be atomic, self-contained and written in the user's first person perspective."* Schema: `MemoryUpdates{create: List[str], delete: List[str ids]}`. - Users can list, edit and delete memories via REST (`/api/memories` GET/PUT/DELETE). — [KH routers/api_memories.py](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/routers/api_memories.py)

**Supermemory**
- The profile API returns `{profile: {static: [...], dynamic: [...]}}`. Static = "Permanent facts that don't change (name, profession, birthday) … High priority in retrieval". Dynamic = "Contextual, episodic … Can be updated or superseded". Versioning uses an `Updates` relation with `isLatest`. `Extends` links enriching information, and `Derives` holds inferred facts (e.g. "User is an ML engineer/researcher" from three memories). — [SM architecture.md#L120-L200, L291-L330](https://github.com/supermemoryai/supermemory/blob/d40b2f5a073a9d2af9aae387583ddd01651babd6/skills/supermemory/references/architecture.md#L120); [SM packages/tools/src/shared/types.ts#L85-L110](https://github.com/supermemoryai/supermemory/blob/d40b2f5a073a9d2af9aae387583ddd01651babd6/packages/tools/src/shared/types.ts#L85)
- **The engine is closed-source**: "Supermemory local — the self-hosted binary — is free within its lite license limit … Its server source is not in the public repository." Local mode defaults to `Xenova/bge-base-en-v1.5` embeddings and can use Ollama (README suggests `gpt-oss:20b`). — [SM apps/docs/self-hosting/local-vs-enterprise.mdx#L8](https://github.com/supermemoryai/supermemory/blob/d40b2f5a073a9d2af9aae387583ddd01651babd6/apps/docs/self-hosting/local-vs-enterprise.mdx#L8); [SM README.md#L314-L340](https://github.com/supermemoryai/supermemory/blob/d40b2f5a073a9d2af9aae387583ddd01651babd6/README.md#L314)

### Inferences
- For Relic, a hybrid makes sense: Memobase-style typed slots for stable facts (the structure makes the profile reviewable and editable), Khoj-style atomic first-person facts for everything else, and Supermemory's static/dynamic split as the injection policy (always inject static; inject dynamic by recency or relevance).
- Memobase's "mention date vs occurred date" convention is cheap and solves a real temporal-reasoning failure. It is worth adopting.
- Khoj's create/delete-only rule avoids silent in-place rewrites and keeps an audit trail if deleted rows are soft-deleted. Memobase UPDATE rewrites the memo in place and loses history.

### Gaps
- Supermemory's isStatic classification, relation detection (Updates/Extends/Derives) and forgetting logic cannot be inspected. The docs describe only behaviour.
- I did not read Memobase's `merge_yolo` (batch-merge) variant or its roleplay modules in detail.

## Q3. How retrieval results are assembled into the prompt

### Takeaway
All five inject plain text blocks with light structure. GA uses timestamped statement lists. A-MEM uses tab-separated metadata lines. Khoj uses a "User's Notes" block with `# URI` headers, plus a `<retrieved_memories>` block marked "Ignore them if they are not relevant". Memobase uses a token-budgeted `# Memory / ## User Current Profile / ## Past Events` block with a 60/40 profile/event split. Supermemory uses `## Static Profile` / `## Dynamic Profile` markdown under "User Supermemories:".

### Cited Findings
- GA: `f"{i.created.strftime('%A %B %d -- %H:%M %p')}: {i.embedding_key}\n"` under a `[Statements]` header, followed by the question. — [GA plan.py#L413-L425](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/plan.py#L413)
- A-MEM: `talk start time:{ts}\tmemory content: {content}\tmemory context: {context}\tmemory keywords: {kw}\tmemory tags: {tags}\n`, followed by the same line format for each linked neighbour. — [AM memory_system.py#L315-L344](https://github.com/agiresearch/A-mem/blob/ceffb860f0712bbae97b184d440df62bc910ca8d/agentic_memory/memory_system.py#L315)
- Khoj documents: `references = "\n\n".join({f"# URI: {item.uri or item.file}\n## {item.compiled}\n" ...})` wrapped in *"Use my personal notes and our past conversations to inform your response. Ask crisp follow-up questions to get additional context, when a helpful response cannot be provided from the provided notes or past conversations. User's Notes: ----- {references}"*. This is injected as a user-role message. — [KH processor/conversation/utils.py#L745-L753](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/processor/conversation/utils.py#L745); [KH prompts.py#L92-L101](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/processor/conversation/prompts.py#L92)
- Khoj memories: the union of `pull_memories` (most recent, `limit=10`, `window=7` days) and `search_memories` (cosine ≤ 0.18, limit 10), deduplicated by id, then rendered as *"Your memory system retrieved the following memories about me based on our previous conversations. Ignore them if they are not relevant to the query.\n<retrieved_memories>\n- [YYYY-MM-DD HH:MM:SS]: {raw}\n</retrieved_memories>"*. — [KH routers/api_chat.py#L978-L983](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/routers/api_chat.py#L978); [KH database/adapters/__init__.py#L2295-L2354](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/database/adapters/__init__.py#L2295); [KH utils.py#L824-L830](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/processor/conversation/utils.py#L824)
- Memobase context packing: `max_profile_token_size = max_token_size * profile_event_ratio` (1000 × 0.6). Profiles are sorted by `updated_at` desc, with `prefer_topics` ranked first and `max_subtopic_size`/`topic_limits` applied. If chats are passed, an LLM "pick related profiles" step chooses up to 10 relevant slot ids (few-shot: "weather → company, college to guess location"). Events are searched with the last 3 chat messages as the query, and `fill_window_with_events` gives leftover profile budget to events. Template: *"---\n# Memory\nUnless the user has relevant queries, do not actively mention those memories in the conversation.\n## User Current Profile:\n{profile_section}\n\n## Past Events:\n{event_section}\n---"*. — [MB controllers/context.py#L27-L193](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/controllers/context.py#L115); [MB controllers/profile.py#L10-L60](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/controllers/profile.py#L10); [MB prompts/pick_related_profiles.py](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/prompts/pick_related_profiles.py); [MB prompts/chat_context_pack.py#L6-L16](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/prompts/chat_context_pack.py#L6)
- Supermemory middleware: profile and search are fetched in parallel, deduplicated between static/dynamic/search, and rendered with `convertProfileToMarkdown` (`## Static Profile` / `## Dynamic Profile`, bullet lists) and the default template `User Supermemories: \n{userMemories}\n{generalSearchMemories}`. Modes are `"profile" | "query" | "full"`, and `addMemory: "always" | "never"`. — [SM packages/tools/src/shared/prompt-builder.ts#L10-L35](https://github.com/supermemoryai/supermemory/blob/d40b2f5a073a9d2af9aae387583ddd01651babd6/packages/tools/src/shared/prompt-builder.ts#L10); [SM shared/memory-client.ts#L45-L160](https://github.com/supermemoryai/supermemory/blob/d40b2f5a073a9d2af9aae387583ddd01651babd6/packages/tools/src/shared/memory-client.ts#L45); [SM shared/types.ts#L60-L72](https://github.com/supermemoryai/supermemory/blob/d40b2f5a073a9d2af9aae387583ddd01651babd6/packages/tools/src/shared/types.ts#L60)

### Inferences
- Common pattern: (1) always-on compact profile, (2) query-retrieved episodic items with dates, (3) an explicit "ignore if irrelevant / don't proactively mention" instruction. Relic should copy all three, with a hard token budget (Memobase's 1000-token, 60/40 split is a good default for small-context local models).
- Khoj's multi-query expansion is its most valuable retrieval trick for personal notes, but it costs one extra LLM call per turn.

### Gaps
- I did not measure how often Khoj's 0.18 cosine-distance cutoff with gte-small returns zero results. Combined with the 0.18 memory cutoff, it looks strict, but I have no empirical data.

## Q4. What can run on small local models

### Takeaway
All embedding and rerank pieces are already small, on-device models (MiniLM-L6, gte-small, mxbai-rerank-xsmall, bge-base). The LLM steps fall into three tiers. Easy for a 1–3B model: 1–10 importance scoring, keyword/tag extraction, query expansion. Moderate: Khoj create/delete facts, Memobase APPEND/UPDATE/ABORT merges. Hard: A-MEM's single multi-output evolution JSON, GA insight generation with evidence indices. A-MEM's own research repo ships Ollama/vLLM backends tested with Qwen2.5-3B.

### Cited Findings
- A-MEM research repo has `OllamaController`, `SGLangController` and `LiteLLMController`, and the README shows runs with `Qwen/Qwen2.5-3B-Instruct` (vLLM) and `qwen2.5:3b` (Ollama) via `test_advanced_robust.py`, which "removes the JSON schema dependency". The code comments acknowledge the small-model failure mode: "if slms output less than the number of neighbors, use the sequential order of new tags and context." — [AMR README.md#L91-L115](https://github.com/WujiangXu/A-mem/blob/0c8039f28fdcc08189a23c07a3437d9d2482f9c2/README.md#L91); [AMR memory_layer.py#L56-L235, L841](https://github.com/WujiangXu/A-mem/blob/0c8039f28fdcc08189a23c07a3437d9d2482f9c2/memory_layer.py#L56); [AMR llm_text_parsers.py](https://github.com/WujiangXu/A-mem/blob/0c8039f28fdcc08189a23c07a3437d9d2482f9c2/llm_text_parsers.py)
- Khoj defaults to local sentence-transformers models (`thenlper/gte-small`, `mxbai-rerank-xsmall-v1`) and has an "offline" variant of the notes prompt (`notes_conversation_offline`). — [KH embeddings.py#L32, L120](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/processor/embeddings.py#L32); [KH prompts.py#L103-L110](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/processor/conversation/prompts.py#L103)
- Memobase uses a line-based `TOPIC::SUB_TOPIC::MEMO` / `ACTION::CONTENT` output rather than JSON. It supports any OpenAI-compatible `llm_base_url` and an `ollama` embedding provider. — [MB env.py#L90-L109](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/env.py#L90)
- GA's importance prompt has `max_tokens: 15`-class outputs (a single integer), and the focal-point call is limited to a short list. — [GA run_gpt_prompt.py#L2100-L2112](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/prompt_template/run_gpt_prompt.py#L2100)
- Supermemory local runs entirely offline with Ollama after the first embedding download (README suggests `gpt-oss:20b`, i.e. not a "small" model). — [SM README.md#L330-L340](https://github.com/supermemoryai/supermemory/blob/d40b2f5a073a9d2af9aae387583ddd01651babd6/README.md#L330)

### Inferences
- Split A-MEM's evolution call into 2–3 single-purpose calls ("which of these 5 are related? → ids", "rewrite tags for note X"), or compute links with embeddings plus a threshold and use the LLM only to label the relation. Small models handle short single-decision prompts far better than parallel arrays that must be index-aligned.
- Line-delimited outputs (Memobase style) and constrained decoding (GBNF/JSON-schema in llama.cpp) are both viable on-device. Memobase's format is the more forgiving of the two.
- Run reflection and profile merging as batched, deferred background jobs (Memobase-style 1024-token buffer or hourly flush; GA-style poignancy budget) while charging or idle, not inline per message.

### Gaps
- No benchmark numbers were collected (arXiv/paper access blocked) on how much A-MEM or GA quality drops with 1–3B models. The README shows the runs exist but not their scores.

## Q5. Weaknesses (bugs and design limits found in code)

### Takeaway
Several concrete bugs show up on reading. GA's recency ranking appears inverted, and its weights differ from the paper. A-MEM (packaged) never runs note construction and maps neighbour updates by search rank onto insertion-order notes. A-MEM links are list indices in the research repo but ids in the packaged one. Khoj and Memobase have no notion of importance or decay beyond time windows. Supermemory cannot be audited.

### Cited Findings
- **GA recency appears inverted (my reading of the code; not verified by execution)**: nodes are sorted ascending by `last_accessed` (oldest first), then `decay**i` for i=1..n is assigned in that order. So the oldest node gets 0.99¹ (highest) and the most recently accessed gets 0.99ⁿ (lowest). The paper's intent is the reverse. — [GA retrieve.py#L145-L152, L224-L228](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/retrieve.py#L145)
- GA recency also depends on rank only: no wall-clock Δt, and it is rescaled with min-max. Normalization runs over *all* memories on every query (brute-force O(N) embedding lookup per focal point). Reflections expire at 30 days, but the `expiration` field is set and not used in `new_retrieve`. — [GA retrieve.py#L224-L249](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/retrieve.py#L224); [GA reflect.py#L124](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/reflect.py#L124)
- GA insight parsing failure returns the placeholder `{"this is blank": "node_1"}`, which is then stored as a thought. — [GA reflect.py#L48-L55](https://github.com/joonspk-research/generative_agents/blob/fe05a71d3e4ed7d10bf68aa4eda6dd995ec070f4/reverie/backend_server/persona/cognitive_modules/reflect.py#L48)
- A-MEM (packaged): `analyze_content` is never called from `add_note`, so construction metadata is empty by default. In `update_neighbor`, `indices` are the 0..k-1 positions in the search results, but they are used to index `list(self.memories.values())` (insertion order), so the wrong notes get their tags/context overwritten. The neighbour text shows `memory index:{i}` rather than ids, yet `suggested_connections` are appended to `links` and later looked up as ids. — [AM memory_system.py#L233-L264, L300-L307, L636-L690](https://github.com/agiresearch/A-mem/blob/ceffb860f0712bbae97b184d440df62bc910ca8d/agentic_memory/memory_system.py#L636)
- A-MEM (research repo): links are integer positions in an insertion-ordered dict (`suggested_connections: integer`), consistent with the corpus there, but they break on any deletion. Evolution only rewrites tags/context; it never merges or deletes contradicting content. — [AMR memory_layer.py#L770-L777, L841-L857, L889-L895](https://github.com/WujiangXu/A-mem/blob/0c8039f28fdcc08189a23c07a3437d9d2482f9c2/memory_layer.py#L841)
- Khoj: fixed 256-word chunks with 0 overlap; memory retrieval is recency (7 days) ∪ cosine with no importance signal; the fact updater sees only the last 2 messages. — [KH text_to_entries.py#L72-L78](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/processor/content/text_to_entries.py#L72); [KH helpers.py#L1004](https://github.com/khoj-ai/khoj/blob/ae229ca894c0b80ad84664afcfdde523b5e87057/src/khoj/routers/helpers.py#L1004)
- Memobase: memos are capped at 5 sentences per slot and rewritten in place (lossy, no history). The schema is census-like (household_income, ethnicity), so a personal app should prune it. — [MB merge_profile.py#L66-L70](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/prompts/merge_profile.py#L66); [MB user_profile_topics.py#L9-L79](https://github.com/memodb-io/memobase/blob/358c16bbc6d687937d79bc2f984a11c3be8da901/src/server/api/memobase_server/prompts/user_profile_topics.py#L9)
- Supermemory: core engine source is not public; only clients, docs and an MIT-licensed SDK/plugins. — [SM local-vs-enterprise.mdx#L8](https://github.com/supermemoryai/supermemory/blob/d40b2f5a073a9d2af9aae387583ddd01651babd6/apps/docs/self-hosting/local-vs-enterprise.mdx#L8)

### Inferences
- If Relic ports GA scoring, it should (a) sort newest-first or use real time decay, (b) normalize with fixed ranges, and (c) honour expiry.
- If Relic ports A-MEM, it should key links by stable ids, run construction explicitly, and store an evolution log (A-MEM has an `evolution_history` field but never writes to it in the packaged code).
- License: GA, Memobase (Apache-2.0) and A-MEM (MIT) code can be adapted with attribution. Khoj is AGPL-3.0: reimplement from the description rather than copying.

### Gaps
- Bugs were found by reading only; nothing was executed (per instructions). The GA recency inversion and the A-MEM index mismatch should be confirmed with a small unit test before relying on these claims.
- I did not check upstream issue trackers for whether these bugs are already reported or fixed in forks.
